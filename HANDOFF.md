# Handoff — Supercuts Analytics

Last updated: 2026-07-25, after adding email-to-auto-upload ingestion (Gmail → Apps Script → new `api/email-report.js` webhook). See "What shipped this session — auto-upload reports from Gmail" below (most recent).

## What this app is
A Store Scoreboard / analytics dashboard for a Supercuts franchise (React SPA, Supabase-backed, deployed on Vercel). Tabs: **Homepage** (default landing tab), **News**, Overview, Stores, Employees, Retail, Color Sales, DL, 60 Day Employee, Reviews, Weekly, and Setup (which also holds Goals / Managers / Milestone Goals / Homepage (News & Events admin) / Historical Import / Upload / **Email Reports** as sub-sections). Has an in-app AI assistant, "Tilly," that answers questions about the business data via a serverless Anthropic API proxy (`api/chat.js`).

## What shipped this session — auto-upload reports from Gmail
The user wanted weekly report emails to upload themselves instead of manual drag-and-drop into Setup > Upload. No domain, no paid inbox-parsing service — built entirely on things the user already has for free (Gmail + Google Apps Script + Vercel).
- **`src/parser.js` refactored, not rewritten**: `parseStylistReport`/`parseEmployeeStartDates`/`parseReviews` (the `File`-taking, `FileReader`-based browser versions) are now thin wrappers around new exported `parseStylistReportFromGrid`/`parseEmployeeStartDatesFromGrid`/`parseReviewsFromGrid(grid, fileName)` — same logic, just grid-in instead of File-in, so it also runs in a Node serverless function with no FileReader/File available. `sheetToGrid` is now exported too. `buildWeeklyRecord`/`mergeWeeklyIntoHistory` were already pure functions, reused as-is. **Browser upload behavior is unchanged** — this was pure code motion, not a logic change.
- **New `api/email-report.js`** (Vercel serverless function): POST endpoint taking `{ secret, type, fileName, contentBase64 }`. Checks `secret` against the `EMAIL_INGEST_SECRET` env var (this endpoint has no user session, so a shared secret is the only gate — treat it like a password), decodes the base64 attachment with `XLSX.read(buf, {type:'buffer'})`, runs it through the matching `...FromGrid` parser, and saves via a direct Supabase call (not `src/db.js`'s `saveData`, which unconditionally touches `localStorage` — not available in a Node runtime). For `stylist_report`, also replicates the weekly-history merge `handleFile` does in `App.js`, but scoped to just the one affected month's chunk (load `weekly_history_<month>`, merge, save back) instead of the browser's full in-memory history — same result, no need to pull every month into memory. Add a new report type by adding one key to the `HANDLERS` map here.
- **New Setup > Email Reports tab** (`EmailReportsSetupTab` in `App.js`) is the in-app walkthrough — mirrors the existing "One-time Supabase setup" card pattern already in Setup > Guide. Shows the full Google Apps Script source (with the real webhook URL auto-filled via `window.location.origin`, but `SHARED_SECRET` always shown as a placeholder — **the real secret is never embedded in the deployed bundle**, since the Setup tab has no password gate and the bundle is public). The script: watches 3 Gmail labels (`SC-StylistReport`, `SC-Reviews`, `SC-EmployeeStartDates`) via a time-driven trigger the user sets up manually (every 30 min), forwards any unread labeled email's attachment to the webhook, marks it read on success, and emails the user directly on failure (leaving the source email unread so it retries next run).
- **Infra side is fully set up as of this handoff**: the Apps Script project ("Supercuts Report Forwarder") is pasted in with the real shared secret, authorized (one-time "unverified app" click-through), running on a 30-minute time-driven trigger calling `checkForReports`, and Vercel's `EMAIL_INGEST_SECRET` env var is set to match the script's `SHARED_SECRET` (the value was generated once and given to the user directly in chat — deliberately never written to this repo; rotate by changing it in both the Apps Script project and Vercel's env vars if it's ever exposed). **Still pending**: the actual Gmail filter + label. The Stylist Report currently arrives as a manual export (no email yet); the user is expecting an automated/corporate system to start emailing it at some point, but the sender address isn't known yet. Once that first email actually lands, create a Gmail filter (From: that sender → apply label `SC-StylistReport`, don't mark as read) — the script is already watching for that label, so nothing else needs to change once the label exists. Reviews and Employee Start Dates aren't part of this yet (no email source identified for those either) — same drill (a label + Gmail filter) whenever/if that becomes relevant, no code changes needed since `api/email-report.js` already handles all three types.
- **Known limitation**: request body size. Vercel serverless functions cap request bodies around ~4.5MB; a base64-encoded attachment runs ~33% larger than the original file. Fine for a normal multi-store stylist-report Excel export, but if the export ever grows much larger (many more stores, or a much wider column set), this endpoint would need chunking or a move to direct blob upload — not needed today.
- **Not done / deliberately skipped**: no automatic Mailparser/Zapier-style inbox service (the user chose the free Gmail+Apps Script route over a ~$15-20/mo paid inbox-forwarding service); no review/approval queue before publish (the user explicitly wants immediate auto-publish, same as manual upload today — a bad emailed file fails the same way a bad manual upload would, just with an email alert since there's no one watching the Setup tab when it happens).

## What shipped this session — News tile grid, group manager, fun headers
Third round, same day, directly addressing the "not done" list from the round below: a real group manager, much smaller News tiles, and bigger/more-fun group headers.
- **News tab is now a grid of small tiles, not a stack of full-width post blocks.** `NewsTab` renders each post as a `HomepageMediaCard` in a new `compact` mode (`.homepage-featured-card--compact`, `.news-tile-grid` — 4-up on desktop, down to 1-up on phones) — roughly a quarter the footprint of the old single-column `.news-post` block it replaces. A tile shows only image/title/date/PDF-badge; description and the "tap to read" hint are dropped from the compact style entirely to keep it a clean thumbnail.
- **Tapping a tile opens the full post in `NewsPostModal`** (new component) — a centered overlay with the full header image, body text, and PDF iframe/download link, reusing the same `.news-post-*` classes the old inline block used. A Homepage News card tap still sets `tab='News'` + `openNews={id}`; `NewsTab` now just opens that post's modal directly instead of scrolling/highlighting a big block — simpler, and works with tiles too small to usefully scroll-to.
- **Real group management**, replacing the old "just a string on a post" version: a new `homepage_news_groups` Supabase key stores `[{name, color}]` in **App** state `newsGroups`, and `NewsGroupManager` (new component, top of `HomepageAdminTab`) lets you rename a group (cascades to every post with the old name), recolor it, reorder it with ↑/↓, or delete it (ungroups its posts — never deletes them). A group typed fresh into the News composer's field auto-registers itself into `newsGroups` via `ensureNewsGroup` (called from `handleAddNews`/`handleUpdateNews`), so there's no separate "create group" step. On load, any group name found on a post but missing from `newsGroups` (e.g. from before the manager existed) self-heals into the list (`NEWS_GROUP_PALETTE` cycling for its auto-assigned color) so nothing typed pre-manager silently stopped being manageable.
- **Group headers are much bigger and more decorative** — `.news-group-label` went from 15px to 34px Barlow Condensed, each one tinted by its group's color (via a `--group-color` CSS custom property set inline) with a fading gradient bar trailing off to the right, plus a cycling emoji (`NEWS_GROUP_EMOJI`, picked by the group's position in the manager's order) for personality. The News tab's bucket order is now the **manager's curated order** (not most-recent-post), with the ungrouped bucket always first and header-less.
- **Not done / deliberately skipped:** no drag-to-reorder (↑/↓ buttons only); no group icon picker (emoji is auto-cycled by position, not chosen); still no automatic contrast check on a group's chosen color against its white header text.

## What shipped earlier this session — edit-in-place, event date ranges/colors, first News-groups pass
Second round, same day, before the tile-grid/group-manager rework above superseded parts of it:
- **News posts and Events can be edited in place**, not just deleted and re-added. `NewsComposer`/`EventComposer` both take an `initial` item (or null for a fresh post) plus `onSubmit`/`onCancel`; `HomepageAdminTab` tracks `editingNewsId`/`editingEventId` and remounts the composer via `key={editingId || 'new'}` when the target changes — that remount is what resets the form fields, no manual sync effect needed. Admin rows got a ✎ button next to the existing ✕.
- **Events support a date range and a calendar color.** `EventComposer` gained a Start/End date pair (`endDate` optional — a bare single day just leaves it blank) and an `<input type="color">` (`DEFAULT_EVENT_COLOR = '#1F3A63'`, matching the old hardcoded pill color). `EventsCalendar`'s `eventsByDay` walks every day of the displayed month and checks range overlap via ISO-string comparison, so a multi-day event shows a pill on every day it spans, each pill tinted with `ev.color`. `FeaturedEvents` treats an event as "upcoming" until its *last* day passes (not just its start) and shows "Happening now 🎉" for an event in progress.
- **News posts gained a group field** (first pass — free-text with a `<datalist>` for autocomplete, no management yet; superseded by the real `NewsGroupManager` in the round above).
- Tilly's context includes each event's end date (`"date to endDate"`) and a news post's group tag.

## What shipped earlier this session — the News tab
Added a dedicated long-format **News** tab, on top of the News & Updates feature already on the Homepage from last session:
- **News posts can now attach a PDF** — `NewsComposer` (Setup → Homepage) gained a `PdfUploadField` next to the existing header-image field. `readPdfAsDataURL` (`App.js`) validates type/extension and caps size at `NEWS_PDF_MAX_MB` (8MB) before base64-encoding inline into the same `homepage_news` jsonb row images already live in — no re-encoding is possible for a PDF the way images get downscaled, so the cap is the only guard against payload bloat.
- **Homepage News cards now navigate instead of opening a lightbox.** `HomepageMediaCard` gained an `onClick` prop that takes priority over the old `onImageClick` (still used by Events, unchanged) — tapping a News card calls `onOpenNews(id)`, which sets `tab='News'` and `openNews={id}` in `App`. Cards with a PDF attachment show a "📄 PDF" badge as a hint before clicking.
- **`NewsTab` (new component in `App.js`)** renders every post in full — full header image, full body text (`white-space: pre-wrap`, no truncation, unlike the 2-line-clamped Homepage teaser), and an inline `<iframe>` PDF viewer plus a `download`-attribute link for the attachment. When arriving via a Homepage card tap, it scrolls to that post and flashes a 2.5s highlight ring (`useEffect` keyed on the `openNews` object — a fresh object reference each click, so re-tapping the same post re-triggers the scroll+highlight even though the id didn't change).
- Wired the PDF-attachment flag into Tilly's context (`buildAIContext`) per standing practice — she now knows a post has a PDF attached, not its contents.
- **Not done / deliberately skipped:** no in-app PDF *editing* (delete + re-add only, matching how News/Events already worked); no OCR/text-extraction of PDF content for Tilly.

## What shipped this session — the Homepage tab
Built from nothing to a fairly rich landing page across several rounds of feedback. Current shape:

- **News & Updates and Events are authored in Setup → Homepage**, not on the Homepage tab itself — mirrors the Goals/Managers pattern (edit in Setup, display everywhere else) so the public-facing landing page can't be edited by accident. `HomepageAdminTab` in `App.js` has a composer + delete-able list for each. Both support an optional **header image**: `ImageUploadField` reads the file, downscales it to ≤960px and re-encodes as a JPEG data URL (`readImageAsDataURL`) before it's stored inline in the Supabase jsonb payload (`homepage_news` / `homepage_events` keys) — this keeps payload size sane since there's no separate blob storage in this app.
- **Events render as a calendar** on the Homepage tab: the 3 soonest upcoming events show as large banner cards (`FeaturedEvents` → `HomepageMediaCard`) above a real month-grid calendar (`EventsCalendar`, prev/next nav, today highlighted, event pills per day).
- **News cards use the same `HomepageMediaCard` component/CSS as the featured events** (`.homepage-card-grid`), specifically so they're sized to match rather than stretching full width — this was a direct user correction mid-session.
- **Click a News or Event card's image to open it full-size** in an in-app lightbox (`ImageLightbox`) — cards crop/shrink the photo via `background-size: cover`, so this is how a flyer/poster's actual text gets read. Deliberately NOT `window.open('data:...')` — modern Chrome blocks top-level navigation to data URLs, so a real in-app overlay was the only reliable option.
- **Top 10 Leaderboards** (Retail, Color Sales, CPH, TSTH) — `TopTenChart`, horizontal bar via `chart.js`/`react-chartjs-2` (already in `package.json`, previously unused). Each has a "⬇ PNG" export button (`chart.toBase64Image()` + a `homepagePngBg` plugin so the export isn't transparent). Lives in the main column below the calendar (moved down from the sidebar per user feedback — a wider column suits a 2-up chart grid better).
- **Sidebar, top to bottom**: "🌟 Shoutouts" (`ReviewSpotlightWidget`) cycles 5-star reviews that name a stylist by name (reuses `detectEmployeeMention` from the Reviews tab), 10s per review, pauses on hover, progress bar. Each review gets tagged with whichever of **Quality / Convenience / Hospitality / Atmosphere** its text matches (`CORE_VALUE_CATEGORIES`, keyword-based — includes generic praise like "great job"/"well done" under Quality, not just explicit skill language). Below it, "🧭 Core Values" (`CoreValuesWidget`) cycles the salon's 4 official values (Serve/Grow/Be a Super Teammate/Commit to Excellence — hardcoded in `CORE_VALUES`, sourced from the internal poster image the user shared) every 20s. Title+subtitle render as one uniform bold-uppercase line (subtitle explicitly inherits the title's font/size/weight — an earlier version styled them differently and the user flagged the mismatch).
- **Bitmoji mascot peeks — Homepage only.** 13 user-supplied bitmoji images live in `src/assets/bitmoji/`, grouped by mood in `src/bitmoji.js` (positive/curious/skeptical/all). `useBitmojiCycler` (in `App.js`) is a **single shared coordinator** — only one mascot is ever visible at a time anywhere on the page, hopping between 6 fixed spots that are each anchored to a specific widget's corner (`BITMOJI_PEEK_CORNERS`) so it never appears at a "random" page position. This was a deliberate rewrite: the first version gave every widget its own independent timer, which could show multiple mascots at once — explicitly not what was wanted.

## Known limitations (deliberate, not oversights)
- Tilly's historical data is **month-level only** — no day/week granularity in her context.
- Review text sent to Tilly is capped at 40 most-recent-negative / 15 most-recent-positive — aggregates/counts are uncapped, only raw quotes are bounded.
- Manager name matching (Setup > Managers) is exact-normalized-name, not fuzzy.
- Homepage News/Events admin (Setup > Homepage) has no password gate — anyone who can reach Setup can post/delete. Same posture as Goals/Managers before this session; add a gate the same way `GOALS_PASSWORD` does it in `App.js` if that's ever a problem.
- News PDFs are base64-inlined into the single `homepage_news` Supabase row (same pattern as header images, capped at 8MB each via `NEWS_PDF_MAX_MB`) — every save/load moves the *whole* news array, so a handful of large PDFs accumulating over time will make that row (and every News edit) progressively heavier. Fine for occasional flyers/memos; if PDF posting becomes frequent, worth moving to real blob storage (Supabase Storage) instead of jsonb.
- No test suite, and **no Node.js/npm in this sandboxed environment** — every change this session was verified by careful re-reading plus a `perl`-based brace/paren balance check, never an actual local build. **After every push, poll `gh api repos/evanrobins6789-cyber/supercuts-analytics/commits/<sha>/status --jq '.statuses[]'`** for the real GitHub↔Vercel compile check — this was done after every commit this session and everything came back green, but it's the only real verification that exists.

## Architecture notes for a fresh session
- `src/App.js` is one large file (~4300+ lines now) — most tabs/widgets are components within it. Read the relevant function directly rather than assuming structure.
- `src/bitmoji.js` + `src/assets/bitmoji/*.png` — new this session, see above.
- `src/db.js`: generic Supabase (`weekly_report` table) + localStorage persistence layer. `loadData`/`saveData`/`clearData` and `*ByPrefix` counterparts all return `{ok, error}` (or `{data, source, error}` for loads) — check these, especially cleanup deletes after a format-swap save.
- `src/leaderRoster.js`: hardcoded DL/Area Supervisor → store-code roster (edited + redeployed on change — different from Managers/Homepage News/Events, which are user-editable in-app).
- The `supercuts-analytics/` subdirectory in the repo root is a **stale duplicate**, not the deployed app — ignore it.
- Deploys automatically via Vercel on push to `main`. Two Vercel projects exist for this repo (`supercuts-analytics` and `supercuts-analytics-llxh`) — the status-check poll above reports both; both need to be green.
